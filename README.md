# ✍️ 블로그 챌린지 관리 앱

블로그 글쓰기 챌린지를 운영하기 위한 웹앱입니다.
관리자가 아이디와 비밀번호를 만들어 챌린지원에게 전달하면, 챌린지원은 그 아이디로 로그인해 블로그 글을 등록하고 진척 상황을 확인합니다.

- 구조: [독서 챌린지 인증 시스템](https://github.com/philosophyAIEDU/260818comingssoni)과 같이 **빌드 도구 없는 정적 HTML/CSS/JS**와 **Firebase(Firestore)**로 만들었습니다.
- **Firebase 무료 요금제(Spark)**에서 무료로 쓸 수 있는 **Authentication(이메일/비밀번호)**과 **Cloud Firestore**만 사용합니다. Cloud Functions와 Storage는 쓰지 않습니다.
- **Vercel**에 그대로 배포할 수 있습니다. 서버 코드는 `api/` 폴더의 서버리스 함수 2개뿐입니다.

---

## 기능

### 로그인 (`index.html`)
- 관리자가 정해 준 **아이디(한글 가능)와 비밀번호**로 로그인합니다. 구글 로그인은 쓰지 않습니다.
- 처음 배포한 뒤 **최초 관리자 계정**을 이 화면에서 한 번만 만들 수 있습니다. 관리자가 생기면 이 버튼은 사라집니다.

### 관리자 페이지 (`admin.html`)
| 탭 | 기능 |
| --- | --- |
| 📈 **진척 현황** | 기준일을 기준으로 챌린지원별 **데일리, 위클리, 먼슬리** 달성 현황, 총 포스팅 수, 연속 달성 일수, 달성률, 검토 대기 수를 보여 줍니다. 아래 **기간별 매트릭스**는 데일리/위클리/먼슬리 단위로 바꿔 볼 수 있습니다. |
| 📝 **포스팅 검토** | 제출된 글을 **검토 후 등록**과 **자유 등록**으로 나눠 보여 줍니다. 상태(검토 대기, 검토 완료, 수정 요청), 챌린지원, 검색어로 거를 수 있습니다. 검토 요청 글에는 ✅ 검토 완료, ✏️ 수정 요청을 누를 수 있습니다. 모든 글 아래에 **500자 이내 코멘트**를 달고 수정하거나 지울 수 있습니다. 챌린지원이 코멘트를 읽었는지, 어떤 반응(👍❤️👏🙏🔥)을 남겼는지도 보입니다. |
| 👀 **방문자 추이** | 챌린지원이 입력한 블로그 **일 방문자 수**를 선 그래프로 보여 줍니다. 전체 합계나 한 사람씩 골라 볼 수 있습니다. 챌린지원별 최근 값, 직전 대비 변화, 평균, 최고 값도 함께 나옵니다. |
| 👥 **챌린지원 관리** | 아이디와 비밀번호를 정해 계정을 만듭니다. 비밀번호는 자동 생성할 수도 있습니다. 여러 명을 한 번에 만들 수도 있습니다. 계정을 만들면 **전달용 안내문**(주소, 아이디, 비밀번호)이 생성되며, 복사해서 카톡 등으로 보내면 됩니다. 이름과 블로그 주소 수정, 기수 이동, 삭제도 이 탭에서 합니다. **비밀번호 재설정**은 서버 설정이 필요합니다(아래 참고). |
| ⚙️ **기수 · 미션 설정** | 미션 **기간(시작일~종료일)**과 **데일리, 위클리, 먼슬리 목표 개수**를 정합니다. **새 기수 시작**을 누르면 새 기수가 만들어져 진척이 0부터 다시 집계되고, 원하면 기존 챌린지원을 계정 그대로 새 기수로 옮길 수 있습니다. 이전 기수 기록은 상단의 기수 선택에서 계속 볼 수 있습니다. 기록을 아예 지우려면 **기수 데이터 초기화**를 쓰고, 관리자 계정도 이 탭에서 추가합니다. |

### 챌린지원 대시보드 (`member.html`)
- **미션 진척**: 데일리, 위클리, 먼슬리 진행 막대와 총 포스팅 수, 🔥연속 달성, 달성률, 날짜별 기록 칸, 주차별·월별 상세를 보여 줍니다.
- **블로그 글 등록**: 📝 **검토 요청**(관리자가 검토)과 🚀 **자유 등록**(바로 기록) 중에서 고릅니다. URL, 제목, 발행일, 관리자에게 남길 메모를 적습니다. 검토가 끝나지 않은 글은 수정하거나 삭제할 수 있습니다.
- **받은 코멘트 뷰어**: 새 코멘트에는 NEW 표시가 붙습니다. 👍 따봉, ❤️ 하트, 👏, 🙏, 🔥 중 하나를 누르거나 ✔ 확인을 누르면 **읽음** 처리되고, 고른 반응은 관리자 화면에 보입니다.
- **방문자 수 추이**: 블로그 통계에 나오는 일 방문자 수를 날짜별로 입력하면 그래프가 그려집니다.
- **비밀번호 변경**: 챌린지원이 직접 비밀번호를 바꿀 수 있습니다.

### 집계 규칙
- 미션 기간 안에 **발행일(postDate)**이 들어가는 글만 진척에 반영합니다.
- **데일리**: 그날 올린 글 수가 하루 목표 이상이면 달성입니다.
- **위클리**: 월요일부터 일요일까지 올린 글 수입니다. **먼슬리**: 달력 기준 한 달 동안 올린 글 수입니다. 기간에 일부만 걸친 주와 달은 걸친 날 수만큼 목표를 줄여서 비교합니다(올림). 예를 들어 주 5회 목표에 기간이 5일만 걸치면 목표는 4회입니다.
- **달성률**: 지난 날짜 가운데 데일리를 달성한 날의 비율입니다. 오늘은 달성했을 때만 계산에 넣어서, 아침에 수치가 갑자기 떨어지지 않게 했습니다.
- 검토 요청 글은 **검토 대기 상태여도 미션으로 집계**됩니다. 검토 상태는 글 품질에 대한 피드백 용도입니다.

> ℹ️ 블로그 방문자 수는 네이버 등 블로그 서비스가 외부에 공개하는 무료 API가 없습니다. 그래서 **챌린지원이 직접 입력**하는 방식으로 만들었습니다.

## 처음 설정하기

### 1. Firebase 프로젝트 만들기 (Spark 무료 요금제)
1. [Firebase 콘솔](https://console.firebase.google.com/)에서 프로젝트를 만듭니다.
2. **Authentication → 시작하기 → 로그인 방법 → 이메일/비밀번호 → 사용 설정**을 켭니다.
   - 같은 화면의 **설정 → 사용자 작업**에서 "계정 생성(가입) 허용"은 **켜 둔 상태로 유지**해야 합니다. 관리자가 브라우저에서 챌린지원 계정을 만들기 때문입니다. 낯선 사람이 가입해도 관리자가 등록하지 않은 계정은 보안 규칙 때문에 아무 데이터도 보지 못합니다.
3. **Firestore Database → 데이터베이스 만들기**를 누릅니다. 위치는 `asia-northeast3 (서울)`을 권장하고, 프로덕션 모드로 시작합니다.
4. **Firestore → 규칙** 탭에 이 저장소의 [`firestore.rules`](firestore.rules) 내용을 그대로 붙여 넣고 **게시**합니다. ⚠️ 이 단계를 빠뜨리면 아무것도 저장되지 않습니다.
5. **프로젝트 설정 → 일반 → 내 앱 → 웹 앱(</>) 추가**를 누르고, 나오는 `firebaseConfig` 값을 적어 둡니다.

### 2. Vercel에 배포하기
1. 이 저장소를 Vercel에서 **Import**합니다. Framework Preset은 `Other`로 두고, Build Command와 Output Directory는 비워 둡니다.
2. **Settings → Environment Variables**에 아래 값을 넣습니다.

   | 이름 | 값 | 필수 |
   | --- | --- | --- |
   | `FIREBASE_API_KEY` | firebaseConfig.apiKey | ✅ |
   | `FIREBASE_AUTH_DOMAIN` | firebaseConfig.authDomain | ✅ |
   | `FIREBASE_PROJECT_ID` | firebaseConfig.projectId | ✅ |
   | `FIREBASE_APP_ID` | firebaseConfig.appId | ✅ |
   | `FIREBASE_MESSAGING_SENDER_ID` | firebaseConfig.messagingSenderId | |
   | `FIREBASE_STORAGE_BUCKET` | firebaseConfig.storageBucket | |
   | `FIREBASE_SERVICE_ACCOUNT` | 서비스 계정 키 JSON 전체 (아래 참고) | 선택 |

   > 환경변수 대신 [`js/config.js`](js/config.js)의 `FIREBASE_CONFIG`에 값을 직접 적어도 됩니다. 웹 앱 설정값은 원래 브라우저에 공개되는 값이라 커밋해도 괜찮습니다.
3. 배포 후 사이트에 들어가 **최초 관리자 계정 만들기**로 관리자 계정을 만듭니다.
4. 관리자 페이지의 **기수 · 미션 설정**에서 첫 기수(예: 1기)와 기간, 목표를 정합니다.
5. **챌린지원 관리**에서 계정을 만들고, 생성된 안내문을 챌린지원에게 전달합니다.

### 3. (선택) 비밀번호 재설정과 계정 완전 삭제 켜기
브라우저용 Firebase SDK로는 다른 사람의 비밀번호를 바꾸거나 계정을 지울 수 없습니다. 그래서 이 두 기능만 Vercel 서버리스 함수(`api/admin-users.js`)에서 처리합니다. Admin SDK의 계정 관리 기능은 **Spark 요금제에서도 무료**입니다.

1. Firebase 콘솔 → **프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성**을 눌러 JSON 파일을 받습니다.
2. 파일 내용 전체를 Vercel 환경변수 `FIREBASE_SERVICE_ACCOUNT`에 붙여 넣고 다시 배포합니다.
   - 키를 세 개로 나눠 넣는 방식도 됩니다: `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`
   - ⚠️ 이 키 파일은 **절대 저장소에 커밋하지 마세요.**

설정하지 않아도 나머지 기능은 모두 동작합니다. 이때 챌린지원 삭제는 앱의 데이터만 지우며, 같은 아이디를 다시 쓰려면 Firebase 콘솔 Authentication에서 계정도 지워야 합니다. 챌린지원은 대시보드에서 비밀번호를 직접 바꿀 수 있습니다.

## 무료 한도 안에서 쓰기
Spark 요금제의 Firestore 무료 한도는 하루 **읽기 5만, 쓰기 2만, 삭제 2만**이고 저장 용량은 1GiB입니다.
- 챌린지원 대시보드를 한 번 열 때 읽기는 대략 "내 글 수 + 받은 코멘트 수 + 방문자 기록 수 + 몇 건"입니다.
- 관리자 페이지를 한 번 열면(또는 ↻를 누르면) 보고 있는 기수의 글, 코멘트, 방문자 기록과 전체 멤버를 한 번씩 읽습니다.
- 실시간 리스너를 쓰지 않고 필요할 때만 읽기 때문에, 수십 명 규모의 챌린지라면 한도에 한참 못 미칩니다.
- 복합 색인이 필요한 쿼리를 쓰지 않아서 **색인을 따로 만들 필요가 없습니다.**

## 보안 메모
- 한글 아이디는 SHA-256 해시를 거쳐 `u<해시>@challenge.example.com` 형태의 **내부용 계정**으로 바뀝니다. 실제 메일은 가지 않습니다. 이 도메인(`APP.idEmailDomain`)을 운영 중에 바꾸면 기존 계정으로 로그인할 수 없게 됩니다.
- 접근 제어는 [`firestore.rules`](firestore.rules)가 맡습니다.
  - **관리자**: `admins/{uid}` 문서가 있는 계정입니다. 모든 데이터를 읽고 쓸 수 있습니다.
  - **챌린지원**: 자기 글, 받은 코멘트, 자기 방문자 기록만 읽습니다. 코멘트에는 "확인/반응" 필드만 바꿀 수 있습니다. 검토 완료된 글은 수정하거나 삭제할 수 없습니다.
  - 그 밖의 로그인 계정은 아무 데이터에도 접근할 수 없습니다.

## 파일 구조
```
index.html            로그인 (+ 최초 관리자 생성)
member.html           챌린지원 대시보드
admin.html            관리자 페이지
css/style.css         공통 스타일 (라이트/다크)
js/config.js          설정 (Firebase 설정, 반응 이모지, 기본 목표 등)
js/utils.js           날짜·진척 계산 (순수 함수, 테스트 대상)
js/firebase.js        Firebase 인증 + Firestore 데이터 계층
js/ui.js              화면 공통 도우미 (토스트, 진행 막대, SVG 그래프, 접근 제어)
js/login.js | member.js | admin.js   페이지별 스크립트
api/firebase-config.js   Vercel 환경변수 → 웹 앱 설정 전달
api/admin-users.js       비밀번호 재설정 / 계정 삭제 (선택)
firestore.rules       Firestore 보안 규칙
test/utils.test.js    진척 계산 단위 테스트
```

## 로컬 개발
```bash
npm test                 # 진척 계산 단위 테스트
npm run serve            # 정적 서버 http://localhost:3000 (js/config.js에 Firebase 설정 필요)
npx vercel dev           # /api 함수까지 함께 실행 (Vercel 환경변수 사용)
```

실제 Firebase 프로젝트 없이 **에뮬레이터**로 시험해 볼 수도 있습니다(Java 필요).
```bash
npm run emulators        # Auth(9099) + Firestore(8080), firestore.rules가 적용됩니다
npm run serve            # 다른 터미널에서 실행
# 브라우저에서 http://localhost:3000/?emulator=1 로 접속
```
